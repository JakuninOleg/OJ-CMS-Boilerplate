# OJ CMS Boilerplate

Готовая основа Next.js + Payload с фирменным интерфейсом OJ CMS. Одна штатная админка: авторизация, формы, коллекции, версии и API работают через Payload. Оформление, меню, поиск и обзор — компоненты OJ CMS. Отдельной конкурирующей панели нет.

В репозитории нет клиентского сайта, контента, фотографий, аккаунтов или ключей доступа. Публичный маршрут `/` направляет в `/admin`.

## Что включено

- Светлая тема OJ CMS, Inter, адаптивное меню, поиск Ctrl+K, календарь, обзор реальных записей и быстрые действия.
- Пользователи с ролями администратора и редактора; редактор не меняет роли и не удаляет пользователей. Последнего администратора нельзя удалить или понизить.
- Страницы и публикации: черновики, версии, Lexical с панелью инструментов и таблицами, SEO-поля, читаемые адреса из русского заголовка.
- Медиа: JPEG, PNG, WebP до 10 МБ; PDF и DOCX до 20 МБ. Проверка содержимого и полной обработки, WebP-копии 480/960/1600 px, защита файлов, используемых в записях и версиях. Сжатие quality 85 — визуально качественное, но не математически без потерь. Оригинал сохраняется.
- Локальное хранение или S3; PostgreSQL с поддержкой доверенного CA; SMTP для восстановления паролей.
- Standalone-сборка, Dockerfile, тесты и GitHub Actions.

## Новый проект

1. Создайте отдельный репозиторий из этого шаблона. Для каждого клиента используйте отдельную БД, бакет/префикс и секреты.
2. Установите Node.js 22+ и зависимости: `npm ci`.
3. Скопируйте `.env.example` в `.env.local`. Заполните `DATABASE_URL` и случайный `PAYLOAD_SECRET` длиной от 32 символов. Для генерации: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
4. Для локальной БД: `docker compose up -d db`. Пароль в compose — только для локальной разработки, не для хостинга.
5. Запустите `npm run dev`, откройте `http://127.0.0.1:3200/admin`. Создайте первого администратора на штатном экране первого запуска. Альтернатива: заполните временные `ADMIN_EMAIL`, `ADMIN_PASSWORD` (от 16 символов), `ADMIN_NAME` и выполните `npm run admin:create`; удалите пароль из окружения после создания.
6. Настройте бренд в `src/oj.config.ts`, замените `public/oj-mark.svg`, при необходимости измените токены в `src/components/cms/oj-admin.scss`.
7. Добавьте свои коллекции и публичные страницы. Для карточек обзора и поиска измените `contentCollections`. Выполните `npm run generate:types` и `npm run generate:importmap`.

Сохранённый slug не меняется при переименовании заголовка. Если меняете адрес вручную, настройте постоянный редирект в клиентском проекте. Шаблон не содержит публичного рендеринга контента и не обещает SEO-оптимизацию будущего сайта.

## Проверки

`npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.

Интеграционный тест создаёт пользователей и записи: **только пустая одноразовая БД**, с переменной `ALLOW_DISPOSABLE_TEST_DB=true` выполните `npm run test:integration`. На Windows: `$env:ALLOW_DISPOSABLE_TEST_DB='true'`. Не запускайте против клиентской БД.

## Продакшен

- Заполните env на хостинге; не добавляйте `.env.local` в Git. `PUBLIC_SITE_URL` должен совпадать с HTTPS-адресом приложения.
- Начальная миграция уже включена. При изменении коллекций генерируйте и коммитьте следующие миграции: `npm run migrate:create`. На отдельной пустой БД проверьте `npm run migrate`, затем выполняйте миграции как шаг релиза перед запуском приложения. Автоматический schema push отключён в production.
- `npm run build`, `npm start`; хостинг передаёт `PORT`, `HOSTNAME=0.0.0.0`. Docker-образ запускает standalone `server.js`.
- Без S3 нужен постоянный диск для `.data/media`. В контейнере это `/app/.data/media`; при `npm start` — `.next/standalone/.data/media`. Эфемерное хранение удалит загрузки при новом деплое.
- Настройте SMTP до передачи клиенту, иначе восстановление пароля не доставит письмо. Почта нигде не отправляется на адреса предыдущего проекта.
- Создайте первого администратора до открытия приложения в интернете. URL медиа публичны: для приватных документов добавьте отдельную коллекцию с защищённой загрузкой и хранением.
- Сделайте бэкапы БД и медиа, проверьте восстановление, права доступа, HTTPS, лимиты и реальные сценарии нового проекта.
- Шаблон закрыт от индексации целиком. Когда добавите публичный сайт, измените правила robots в `next.config.mjs` и метаданные публичного layout, сохранив noindex для админки и API.
- Пиксельный лимит остаётся внутренней защитой памяти; пользователю показывается лимит в мегабайтах и ссылка на Squoosh. Проверка DOCX/PDF не заменяет антивирус.

Аналитика, заявки, каталог, интеграции и frontend добавляются под конкретный проект. Здесь нет чужих счётчиков или демонстрационной статистики.

Известные предупреждения зависимостей и ограничения описаны в `SECURITY.md`. Перед каждым клиентским релизом повторяйте аудит.
